## Remediation pass (verify-caught, fixed by hand)

1. **PHI field count was 37 → corrected to 39 library-wide.** The fact-gathering agent miscounted `PHI_FIELDS`
   (actual: User 6 + Biomarker 2 + BiomarkerHistory 1 + UserFile 1 + InsurancePlan 2 + ProviderPatient 1 + HealthNeed 1
   + HealthGoal 4 + GoalProgressHistory 2 + AuditLog 3 + ExpenseProjection 3 + ExpenseActual 8 + CostAnalysis 3 +
   LabConnection 2 = **39** across 14 models, `encryption.ts:476-562`). The wrong "37" propagated via the canonical
   block to 11 files; the adversarial verify pass flagged it; fixed everywhere (19 replacements / 11 files).
2. `00-index` / `_review-protocol` — security-prompt range corrected to `41-45` (an editor over-wrote it to `41-46`/`41-43`).
3. `17-api-reference-doc` — worked-example citations corrected to live lines (`authController.login:270`,
   `biomarkerController.getBiomarkers:143`, `biomarkerRoutes POST / :85`).
4. `43-plan-gating-billing` — the "expect ZERO hits → known gaps" verification comment corrected (maxBiomarkers/insurancePlans
   are now enforced; providerSharing is intentionally ungated, not a gap).
5. `_verification-tools` / `23-financial-tracker-doc` — missed date bump / stale "18 models".
6. **`New Project Documents/` was NOT populated** (found 2026-06-16 while running the doc prompts). The audit agent had
   asserted a detailed ~18-docs + 3-reports listing that turned out to be a **hallucination** (a later `Glob` showed the
   folder empty), and its verifier trusted the listing. The resulting `25-full-doc-refresh` / `14-strategy-doc` "populated /
   incremental / cross-links resolve" edits were reverted to "may be empty; first run = from-scratch; verify before cross-linking."
   **Method lesson:** a claimed directory/file *listing* is itself a citation — the verify pass must re-run the `Glob`/`ls`, not trust the asserted list.

**Method lesson:** an authoritative fact set is only as good as its counts — have the adversarial verify pass
re-count any number the canonical block asserts, not just per-file claims.

## Code-side findings surfaced during the refresh

These are *code* issues (not prompt drift) the agents surfaced while citing. Each is cited; confirm before acting.

1. **Series-merge bypass on upload (data-integrity).** Manual/batch/FHIR biomarker writes funnel through
   `upsertBiomarkerReading`, but the **PDF/OCR lab-upload ingestion path** (`controllers/upload/shared.ts:~244`) still
   does a raw `tx.biomarker.create`, so uploaded labs create disconnected rows instead of appending to the series —
   the exact problem the series fix solved for the other paths. Documented as a Known Gap in `46-biomarker-series`.
2. **L24 filename backfill not yet run in prod.** New uploads encrypt `originalFilenameEncrypted`; legacy
   `user_files.original_filename` rows are still plaintext (reads fall back). Run `backfill-userfile-filenames`
   (dry-run → `--apply`), then drop the plaintext column. (See `45-maintenance-jobs`.)
3. **Document AI not dollar-accounted.** `aiSpendGuard`/`aiCostTracker` bound only Claude token spend; the paid
   Document AI OCR call (`ocrService.processDocument`) has no `trackAIUsage`, so its spend never accrues against
   `AI_DAILY_BUDGET_USD` (bounded only by `pdfUploadsPerMonth` + rate limit). Noted in `09`, `23`, `42`.
4. **`pdf-lib` is now an unused dependency** (its only consumer `pdfRedaction.ts` was deleted) — removal candidate (`13`).
5. **FHIR `CONNECT_FAILED` audit has `userId: undefined`** on pre-exchange failures, and OAuth denial/missing-param
   redirect branches return un-audited (narrowed residual; `05`, `41`).
