## Bonus — code-side findings surfaced during verification

These are *code* issues (not prompt drift) the adversarial verify agents found while checking citations.
Each is cited; confirm before acting.

1. **Dead export:** `csrf.ts` exports `ensureCsrfToken` but nothing imports it — the live token path is
   `csrfProtection` → `setCsrfCookie`. Candidate for removal.
2. **Designed-but-unwired:** `utils/pdfRedaction.ts` `redactPatientBanner()` has **zero callers**. There is
   deliberately no Claude Vision fallback (`claudeExtraction.ts:~87`, `sbcExtraction.ts:~750` reject scanned PDFs
   to OCR). Either wire it or delete it.
   - **Status (2026-06-16): actioned — deleted.** `backend/src/utils/pdfRedaction.ts` no longer exists (removed in
     the post-06-01 dead-code cleanup); `redactPatientBanner` has zero references anywhere in `backend/src` and
     `pdf-lib` is now unused. Do not treat the path/symbol above as a live TODO.
3. **Wrong status code in mental model:** `aiSpendGuard` fails **closed with `503 SERVICE_UNAVAILABLE`**, not 429.
   The 429 on AI routes is the separate `aiLimiter`.
4. **Spend-cap coverage gap:** `aiSpendGuard` (the dollar budget breaker) guards 5 routes
   (`POST /biomarkers/:id/guidance`, `POST /expenses/analyze`, `POST /ai/chat`, `POST /insurance/upload-sbc`,
   `PUT /insurance/plans/:id/reanalyze`). The Claude-backed `/upload/*` routes (`lab-report`, `insurance-sbc`,
   `lab-results-ocr`) carry `aiLimiter` + the `pdfUploadsPerMonth` plan cap but **no dollar breaker** — notably
   `/upload/insurance-sbc` runs the same SBC extraction that *is* dollar-capped on `/insurance/upload-sbc`.
   See `42-ai-cost-control.md` §2 for the authoritative guarded-vs-unguarded enumeration.
   - **Status (2026-06-16): actioned — gap closed.** All three `/upload/*` routes now carry `aiSpendGuard`
     (`uploadRoutes.ts:21` import; `:82` lab-report, `:104` insurance-sbc, `:135` lab-results-ocr). `aiSpendGuard`
     now guards **8 mount points across 5 route files** (aiRoutes, uploadRoutes ×3, biomarkerRoutes, expenseRoutes,
     insuranceRoutes ×2), not 5. The asserted upload-route gap no longer exists. (Also note `isAISpendExceeded` was
     deleted in favor of `admitAISpend()` reserve/settle with a pluggable InMemory/RedisSpendStore.)
5. **Audit gap (narrowed on review):** the *successful* OAuth connect callback **is** audited — `persistConnection`
   writes `operation:'CONNECT'` (`labSyncService.ts:172-177`), alongside sync (`SYNC`/`SYNC_FAILED`) and disconnect
   (`DISCONNECT`). The genuine gaps are narrower: connect **initiation** (`buildConnectRedirect`) is unaudited, and
   callback **failures** have no `CONNECT_FAILED` row. Full analysis in `41-fhir-lab-integration.md` §4.
   *(The `05-audit-logging` refresh pass initially overstated this as the whole callback being unaudited; corrected.)*
   - **Status (2026-06-16): actioned — mostly closed.** Connect **initiation** is now audited (`CONNECT_INITIATED`
     in `buildConnectRedirect`, `labSyncService.ts:104-109`) and callback **failures** now write a `CONNECT_FAILED`
     row (`fhirController.ts:116-129`). Residual gap is narrower: the `CONNECT_FAILED` row has a null user binding
     (the PKCE-bound `userId` is consumed on success, so the catch logs `userId: undefined`), and the
     OAuth-denial / missing-param branches are still unaudited.
6. **Latent redaction gap:** `logger.ts` `SENSITIVE_FIELDS` matching lowercases keys (`key.toLowerCase()`), but
   several set entries keep mixed case (`accessToken`, `refreshToken`, `claudeResponse`, `responseText`) and so can
   never match.
   - **Status (2026-06-16): actioned — fixed.** Every `SENSITIVE_FIELDS` entry is now lowercase
     (`accesstoken`, `refreshtoken`, `clauderesponseencrypted`, `responsetext`) with an explicit "MUST be lowercase"
     comment (`logger.ts:28-41`), and matching is `SENSITIVE_FIELDS.has(key.toLowerCase())` (`logger.ts:76`). The
     never-match bug no longer exists.
7. **Silent no-op test scripts:** backend `npm run test:unit` / `test:integration` point at
   `src/__tests__/unit` / `src/__tests__/integration`, which **do not exist** → `--passWithNoTests` makes them run
   zero tests. Real backend suite is `npm test` / `test:ci`.

## New prompts created (2026-06-01)

Three product domains were large enough to warrant their own prompts. All three were drafted as deep
single-domain owners (cross-linking to the survey prompts rather than duplicating them), adversarially
verified against the code (0 fabricated citations), and registered in `00-index.md` + `24-full-security-audit.md`.
Security-prompt total is now **23**.

- **`41-fhir-lab-integration.md`** (High, 59 checks) — SMART-on-FHIR OAuth/PKCE (`fhir/smartAuth`), encrypted
  `LabConnection` token lifecycle, SSRF allowlist (`fhir/urlSafety.ts`), sync IDOR, LOINC integrity, audit parity.
  Surfaced: connect-initiation unaudited + no `CONNECT_FAILED`; PKCE cache single-instance; DNS-rebinding residual.
- **`42-ai-cost-control.md`** (High, 34 checks) — `anthropicClient`, `aiCostTracker`, `usageTracker`, `aiSpendGuard`,
  `AI_DAILY_BUDGET_USD` / `AI_USER_DAILY_BUDGET_USD`. Owns the dollar/usage governance (BAA/PHI stays in 27).
- **`43-plan-gating-billing.md`** (Medium, 42 checks) — `planGating`, `config/plans.ts`, `PlanType`,
  `requirePlanFeature`/`requirePlanLimit`, unwired Stripe TODO. Surfaced: `insurancePlans`/`maxBiomarkers` limits
  counted but **never enforced**, `providerSharing` flag ungated, fail-open-to-stale-plan on DB error, a TOCTOU
  window on finite limits, and unlimited tiers bounded only by the AI dollar budget.
  - **Status (2026-06-16): actioned (M12/M13).** `maxBiomarkers` is now enforced via
    `requirePlanLimit('maxBiomarkers')` on biomarker create/batch and the upload routes
    (`biomarkerRoutes.ts:87,105`), plus an in-handler truncation; `insurancePlans` is now enforced on plan create
    plus an in-handler activation gate (`insuranceController.ts`). `checkPlanLimit` does a numeric compare
    (`usageTracker.ts:156-209`). The "never enforced" characterization is reversed. (`planGating` now also fails
    **CLOSED to FREE** on DB error, not to the stale JWT plan; `providerSharing` is `true` on all tiers by product
    decision. The finite-limit TOCTOU window — L34/L36 — remains a documented-accepted race backstopped by the
    dollar spend-cap.)
